# hxwl-05 换水排程台

多鱼缸水质监测 + 换水排程：鱼缸登记水量、检测状态与维护优先级；异常未复测合格不能排换水；按日期共享换水额度、高优先级先占用；已执行排程冻结，只能带原因修订。

## 技术栈

React + Vite + TypeScript + CSS（无新增依赖，数据 / 规则 / 页面分层）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5105。数据持久化在浏览器 localStorage（key：`hxwl-05-water-change-station-v1`），右上角「恢复示例数据」可一键还原种子场景。

## 分层结构

- `src/scheduler/types.ts` —— 领域类型：鱼缸、检测、排程、额度、冲突、修订链
- `src/scheduler/seed.ts` —— 初始示例数据（日期相对今天生成）
- `src/scheduler/rules.ts` —— 纯规则引擎，不依赖 React / 存储，可独立单测
- `src/scheduler/store.ts` —— 状态与 localStorage 持久化；所有写操作先过规则预检
- `src/components/` —— 页面层：鱼缸登记 / 检测录入、排程台、冲突清单、弹窗
- `src/App.tsx` —— 组装

## 排程规则（规则只在 `rules.ts` 维护一份）

| 编号 | 规则 |
| --- | --- |
| R1 | 准入：最近检测异常且之后无复测合格的鱼缸禁排换水；无检测记录同样禁排 |
| R2 | 共享额度：同日换水总额不得超过当日上限；高优先级先占，同级按登记时间先占 |
| R3 | 调整：修改未执行项先释放其原占用额度，再按优先级整体重算，任何方案超额都拒绝（含被挤掉的低优先级单） |
| R4 | 冻结修订：已执行排程冻结不可改/删，只能带原因新建修订，旧值完整保留并串联修订链 |
| R5 | 单次换水量不得超过鱼缸登记水量 |

## 一致性设计

- 额度占用、剩余量、冲突**不单独存储**，每次渲染和刷新都由鱼缸 / 检测 / 排程数据经规则引擎实时推导。
- 冲突清单列出：鱼缸、日期、缺口升数、触发规则编号；区分「本次操作被拦截（未写入）」与「现存冲突」。
- 被 R1/R5 判定无效的未执行单不占用额度（不能执行就不抢占他人），但保留数据并挂出冲突，复测/修正后自动重新进入分配。
- 已执行项是历史事实，永远据实占用；其后续修订以未执行项身份进入分配并受全部规则约束。
- 修订链在加载后做完整性自检（链不断、修订必有原因）。
